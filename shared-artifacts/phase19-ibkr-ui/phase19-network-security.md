# Modelo de amenazas y red privada

Activos: TWS Paper, token del agente, datos de cuenta, CSV SIP, opciones IBKR/OPRA, diario privado. Amenazas: publicación de TWS/API, suplantación y replay de agente, confusión Paper/Live, mensajes de orden, exfiltración del navegador, datos retrasados etiquetados como live y fuga en Git.

Controles implementados: TWS exclusivamente loopback; HTTP web exclusivamente localhost; receptor agente solo IP específica de loopback/RFC1918/Tailscale, nunca 0.0.0.0; agente inicia conexión saliente; secreto Bearer distinto de IBKR, comparación temporal segura; origen de navegador restringido, token local para POST y WebSocket, body/payload limitados; mensajes Zod versionados y lista cerrada; secuencia, UUID y límite de tasa; Paper obligatorio, Live deshabilitado; HMAC de cuenta y almacenamiento privado ignorado por Git. No existe ruta de órdenes. Una pérdida de enlace no crea ticks artificiales. El token local presupone que el equipo B y su navegador son confiables; no basta para acceso remoto.

En Windows: instalar Tailscale en ambos dispositivos; aprobar cada dispositivo; usar una política grant/ACL que permita SOLO A hacia B:4301, no hacia TWS 7497 ni API 4300; denegar otros pares/puertos; ligar TRADING_POC_AGENT_HOST a la IP Tailscale exacta de B y TRADING_POC_BACKEND_AGENT_URL a esa IP; configurar el mismo secreto aleatorio fuerte en A y B. Validar estado con agente MOCK primero. No habilitar Tailscale Funnel, router port forwarding ni servidor Vite en red. Tailscale protege el transporte; el secreto protege adicionalmente la aplicación. Antes de acceso web remoto hacen falta TLS, login, autorización, CSRF, respaldo y revisión de licencias.
