# Arranque Windows: `spawn EINVAL`

El lanzador anterior entregaba `npm.cmd` a `child_process.spawn` con `shell:false`. En Windows, invocar así un archivo `.cmd` puede producir `spawn EINVAL` con Node 24. `scripts/dev.mjs` ahora localiza `npm-cli.js` mediante `npm_execpath` y ejecuta `process.execPath` con un arreglo de argumentos, sin `shell:true`. Esto evita interpolar rutas con espacios dentro de comandos de shell.

Antes de iniciar, comprueba que API y Vite puedan ocupar sus puertos. Se admiten `TRADING_POC_API_PORT` y `TRADING_POC_WEB_PORT`; Vite usa `strictPort` para no cambiar de puerto silenciosamente. Un hijo que falla detiene al otro y propaga un código no cero. En Windows la terminación usa `taskkill /T /F` para el árbol npm; en POSIX usa el grupo de procesos. También maneja Ctrl+C. La detección de entrada usa rutas reales para funcionar desde una junction con espacios.

En este Windows con Node 24.20.0 se observaron API y Vite sirviendo por puertos locales configurables. El Ctrl+C inyectado por la terminal de automatización no cerró la sesión dentro de la ventana de espera; este sandbox también negó a `taskkill` inspeccionar y terminar el árbol. Se detuvieron manualmente los procesos de prueba. El lanzador ahora intenta terminar el hijo directo si `taskkill` falla. El script de humo de CI prueba una ruta con espacios, ambos HTTP, cierre de puertos y fallo de un hijo en matrices Node 22 y 24. [Windows CI pasó en ambas versiones](https://github.com/Draxton27/Trading-POC/actions/runs/39197162416). El cierre real mediante Ctrl+C en Git Bash del operador sigue pendiente.

La primera ejecución de CI encontró un defecto en el propio fixture: `tsx watch` permanece vivo cuando falla la configuración de la API, por lo que un modo inválido no prueba la salida de un hijo. El fixture corregido inicia un script npm inexistente junto a Vite. Localmente devolvió código 1 y liberó el puerto de Vite; después pasó en la matriz Windows.
