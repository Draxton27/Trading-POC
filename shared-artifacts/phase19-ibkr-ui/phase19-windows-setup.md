# Instalación local Windows 10/11

1. Instalar Node.js 22 LTS o superior y Git para Windows. Abrir PowerShell, clonar el repositorio y situarse en su raíz. Ejecutar npm ci. El módulo SQLite usa binario nativo: si falla en su Windows, conservar el error completo para diagnosticar Node/arquitectura y ejecutar el workflow Windows; WSL/Docker no son requisitos.
2. Iniciar DEMO con .\scripts\windows\Start-TradingPoc.ps1 -Mode DEMO y abrir http://127.0.0.1:5173 solo en ese equipo. No necesita TWS ni credenciales. Comprobar opciones, gráfico y diario. Para detener, Ctrl+C.
3. OFFLINE: colocar los CSV NVDA, QQQ y SMH autorizados de 15 minutos, sus .meta.json y .calendar.json en trading_poc_001_bollinger/data. Ejecutar .\scripts\windows\Start-TradingPoc.ps1 -Mode OFFLINE. Los CSV no están incluidos en Git.
4. PAPER en B: copiar apps/api/.env.example a .env en la raíz y ajustar TRADING_POC_MODE=PAPER, rutas privadas, TRADING_POC_AGENT_HOST a IP Tailscale específica de B y un TRADING_POC_AGENT_SECRET aleatorio de 32+ caracteres. Configurar firewall de Windows para que solo A alcance B:4301 por Tailscale. Ejecutar Start-TradingPoc.ps1 -Mode PAPER.
5. Instalar Tailscale en ambos equipos, aprobar las identidades y restringir grants/ACL a A -> B:4301. No usar Funnel, IP pública ni reenvío de puertos. En A, instalar el mismo commit del repositorio, ejecutar npm ci, copiar apps/ibkr-agent/.env.example a .env raíz; fijar URL ws://IP_TAILSCALE_B:4301/agent/v1/connect, secreto compartido e ID de agente.
6. En A, abrir TWS Paper y autenticarse manualmente. Habilitar API socket Read-Only en TWS, permitir 127.0.0.1 y comprobar puerto configurado (habitual 7497). Definir IBKR_EXPECTED_PAPER_ACCOUNT exactamente; el agente compara la cuenta, no deduce Paper por puerto. Iniciar .\scripts\windows\Start-IbkrAgent.ps1 -Mode TWS. Probar antes -Mode MOCK; debe aparecer PAPER SIMULADO, nunca como datos reales.
7. Diagnóstico: GET /api/v1/health y /broker/status en B; revisar modo, accountVerified, feedType y timestamps. Sin conexión, usar DEMO u OFFLINE. Las comisiones y ejecuciones antiguas no se infieren si TWS no las entrega. El login, segundo factor y permisos de feed pertenecen a TWS y al usuario. No configurar credenciales IBKR en .env.

Comandos de calidad desde raíz: npm run typecheck; npm test; npm run build; npm run test:e2e. Test-TradingPoc.ps1 ejecuta la primera terna. El navegador de Playwright puede requerir instalación local del paquete Chromium si no está presente. La prueba física de dos computadoras y TWS auténtica está pendiente de equipos y cuenta autorizada.

`npm run dev` usa Node para ejecutar `npm-cli.js`, incluso si el repositorio está en una ruta con espacios. Si los puertos 4300 o 5173 están ocupados, detenga el servidor previo o defina `TRADING_POC_API_PORT` y `TRADING_POC_WEB_PORT` en ambos servicios. Vite no elegirá otro puerto silenciosamente. En PowerShell con política restrictiva, use `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\Start-TradingPoc.ps1 -Mode DEMO` según la política de su equipo. El script `scripts/windows/dev-smoke.ps1` se ejecuta en CI para Node 22 y 24; la verificación física idéntica desde Git Bash continúa pendiente.

Prueba posterior TWS Paper: anote primero la cuenta Paper mostrada por TWS y habilite API Read-Only/loopback; arranque el backend B en localhost y el receptor privado B:4301; verifique ACL A→B:4301 y secreto compartido; arranque el agente A, compruebe NVDA, QQQ y SMH con feed/timestamps, luego cinco contratos NVDA, bid/ask y sus permisos; desconecte y reconecte una vez; compruebe que no aparece ningún método de órdenes. Nunca coloque contraseñas del bróker en `.env`.
