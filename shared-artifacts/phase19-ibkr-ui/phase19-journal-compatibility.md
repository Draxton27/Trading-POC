# Diario F17 desde la interfaz F19

Las nuevas escrituras de la UI terminan en el ledger original F17, bajo el directorio privado `phase17-private/ledger`. Se usa `appendPhase17Decision` y su CSV canónico: preserva ID derivado de SHA-256, CSV fuente, hora de decisión, hora de documentación del servidor, campos de contexto, contratos, capturas verificadas, referencias a fills, revisiones posteriores y cadena append-only. La UI permite importar el CSV F17 completo para conservar esos campos. El formulario breve NVDA se convierte a CSV F17; deja `observedMarket` desconocido y se clasifica `timing_unverified` aunque el operador seleccione `live`.

La clasificación prospectiva requiere una decisión F17 `live` con mercado observado explícitamente y documentación antes del fin del desenlace de referencia. Una reconstrucción o anotación posterior nunca gana esa clasificación. La etiqueta de usuario por sí sola no prueba que el contexto estuviera disponible. Las capturas opcionales se verifican por hash cuando se referencian; el formulario breve no crea capturas ni vínculos de ejecuciones. Para revisiones o datos históricos completos se importa el CSV oficial.

Los registros previos de `phase19-journal` se consultan como `legacyItems` solo lectura; no se reescriben ni se migran implícitamente. Las pruebas comprueban compatibilidad CSV, no operar, revisiones, duplicados idempotentes, hash y preservación de campos. El ledger F17 original solo acepta NVDA. El importador de operaciones F17 usa UTC explícito y deja resultado neto nulo si faltan comisiones. Su cálculo nominal ×100 no verifica contratos ajustados; en la vista se ocultan los resultados de raíces OCC distintas de NVDA/QQQ/SMH y todo multiplicador debe cotejarse con el bróker.
