# Fase 17: método discrecional documentable

Esta entrega define qué información debe observarse y cómo conservarla, sin afirmar que el método humano esté ya confirmado ni que sea rentable. El [método](phase17-method-specification.md) separa declaraciones, hipótesis, datos y ambigüedades. El [registro de evidencia](phase17-operator-evidence-register.csv) contiene 35 afirmaciones originales atribuidas al operador y `PRE07_V2`, una aclaración posterior documentada el 2026-10-18 mediante mensaje y captura del usuario; los 35 registros originales conservan `resumen_conversacional_de_audio_pendiente_de_cotejo`. Véase el [anexo de Recom](phase17-recom-evidence-addendum.md). No es una transcripción certificada. El [catálogo](phase17-feature-catalog.csv) enumera 37 descriptores candidatos con temporalidad, fórmula, datos y primera disponibilidad. Las [preguntas abiertas](phase17-open-questions.md) documentan lo que falta confirmar. Ningún audio, captura ni operación real se publica aquí.

Los otros archivos son la [plantilla humana](phase17-human-decision-template.csv), el [esquema de fills del bróker](phase17-broker-trades-schema.json), el [contrato futuro de cotizaciones de opciones](phase17-options-data-schema.json), el [diseño de comparación](phase17-comparison-design.md), la [mejora del importador](phase17-broker-import-improvements.md), los [resultados de prueba](phase17-import-test-results.json), la [auditoría de integración](phase17-integration-audit.md), el [informe de validación](phase17-validation-report.md) y [SHA256SUMS.txt](SHA256SUMS.txt). La plantilla contiene solo cabecera; no hay decisiones inventadas.

## Uso privado

En `trading_poc_001_bollinger/`, ejecute `npm ci`, `npm run typecheck` y `npm test`. Copie la plantilla, escriba una sola decisión en español y ejecute `npm run journal:phase17 -- /ruta/privada/decision.csv`. `recordMode` requiere `live`, `historical_reconstruction` o `post_outcome_annotation`; `documentedAtUtc` lo fija el sistema. El importador también acepta las cabeceras CSV antiguas de Fases 16 y 17. Los campos desconocidos quedan vacíos. Para `no_trade`, use `direction=no_trade` y `operationType=no_trade`; `rejectedSignalIds` solo se utiliza si la señal fue rechazada explícitamente y `observedMarket=true`.

`contextKnownAtUtc` es la hora declarada de adquisición del contexto humano; si falta o es posterior a la decisión, los indicadores se ocultan en la vista previa. Una hora declarada no prueba por sí sola que se consultó el dato. Para anotar una operación después, use otra fila de plantilla con `recordMode=post_outcome_annotation` o `historical_reconstruction`, `relatedDecisionId` igual al ID original y `linkedExecutionIds` separados por `|`. Puede añadir `exitReason`, `planChangedAtUtc` y `planChangeReason`; cada cambio crea una nueva entrada y nunca edita el plan inicial. Los fills solo se vinculan a una decisión de operación, no a `no_trade`, y deben haberse importado ya.

Para un archivo original PNG/JPEG/WebP: `npm run attach-chart:phase17 -- /ruta/privada/grafico.png ID_CAPTURA [horaUTC]`. El original se copia por hash a almacenamiento privado y se conserva su hora declarada y `mtime` del archivo, identificado como metadato no verificado. Relacione su ID y SHA-256 con la decisión. Los niveles o anotaciones manuales permanecen separados de los niveles calculados; si no conoce su hora de trazado, no se atribuyen a una decisión anterior.

El CSV del bróker contiene una fila por fill y exactamente la cabecera del esquema. Ejecute `npm run import:broker:phase17 -- /ruta/privada/A.csv` y repita por cada archivo B, C, etc. `npm run broker-state:phase17` reconstruye todas las fuentes originales privadas y muestra hash, posiciones y contratos abiertos. Reimportar el mismo archivo no crea fills nuevos; solapamientos idénticos se deduplican y contradicciones abortan. Compras y ventas parciales se casan FIFO por OCC entre archivos; las comisiones vacías dejan el neto calculado en `null`. Los sobres originales, con SHA-256 y hora de importación, quedan en `output/phase17-private/broker-sources/` y no se publican. Los JSON one-off del importador anterior requieren reimportar sus CSV originales: no se migran sin los bytes fuente. No mezcle cuentas ni formatos de spreads/ventas para abrir en el mismo almacén.

`npm run review-trades:phase17` crea una vista **privada** que une decisiones, capturas referenciadas, fills, comisiones, salida y cambios de plan, con el contexto inicial separado del resultado. `npm run compare:phase17` relaciona el diario con señales F16 sin desenlaces posteriores. Ninguno de estos comandos calcula rentabilidad de una estrategia ni convierte reconstrucciones en decisiones prospectivas.

`PHASE17_PRIVATE_DIR` permite elegir el directorio privado persistente. `PHASE16_JOURNAL_DIR` apunta al diario de señales congeladas; el valor predeterminado es `shared-artifacts/phase16-forward-observation/live/ledger`, que puede estar vacío antes de iniciar la observación real. Una comparación sin señales o sin decisiones humanas reales solo comprueba el funcionamiento, no aporta evidencia de desempeño.

Por defecto, diario, capturas, importaciones y comparaciones quedan en `trading_poc_001_bollinger/output/phase17-private/`, excluido de Git. Conserve una copia privada persistente: el directorio temporal de Codex no garantiza continuidad entre entornos. Revise la privacidad antes de compartir cualquier resultado humano. Esta fase no solicita datos masivos de opciones, no ejecuta órdenes y no modifica las reglas congeladas.

Verifique el paquete publicado desde este directorio con `sha256sum -c SHA256SUMS.txt`.
